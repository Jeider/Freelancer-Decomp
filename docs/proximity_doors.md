# Автоматические двери и Act_Animation

Параметры читаются непосредственно из `[Solar]` в `solararch.ini`. Без
`proximity_door = true` автоматического сканирования у объекта нет.

```ini
[Solar]
nickname = lair_proximity_door
; обычные параметры модели, материалов и физики
proximity_door = true
door_scan_radius = 800
door_release_radius = 1100
door_close_delay = 3
anim_open = sc_door_open
anim_close = sc_door_close
door_open_sound = lair_door_open
door_close_sound = lair_door_close
```

Подготовщик добавляет готовый `lair_proximity_door` на основе `lair_anim_door`.
У него удалены параметры штатной стыковки. В `[Object]` системы достаточно
указать `archetype = lair_proximity_door`; миссия и F3 не нужны.
Не добавляйте этой двери старые `InternalFX` с `use_animation`: они будут
одновременно управлять теми же створками.

Сервер проверяет корабли игроков и NPC 10 раз в секунду. Расстояние считается
от центра двери с учётом радиуса корпуса корабля. Обломки, астероиды и оружие
сканер не активируют. Дверь открывается при входе в ближний радиус, остаётся
открытой до выхода всех кораблей из дальнего и закрывается после задержки.
Радиус отпускания автоматически ограничивается снизу радиусом открытия + 1.
Параметры по умолчанию: 800, 1100 и 3 секунды. Если имя одной из анимаций не
задано, автоматический режим не включается. Отсутствующая или не конечная
анимация отключает управление этой дверью с записью в лог.

Повторное присутствие не перезапускает клип или звук. Начавшееся открытие
завершается, даже если корабль сразу улетел. Возвращение во время закрытия
разворачивает **текущий клип закрытия с текущего времени**, без перехода на
другую траекторию и без скачка положения. Начало `anim_close` должно
соответствовать открытому положению, конец — закрытому; для `anim_open` наоборот.
Звуки пространственные, однократные и привязаны к объекту.

В `lair_door01.cmp` добавляются `sc_door_open` и `sc_door_close`: копии
`sc_open_forever` и `sc_close_forever` без последнего кадра удержания на
10^16 и 10^10 секундах соответственно. Оба новых клипа длятся 3,333333 секунды,
управляют шестью створками и сохраняют исходные траектории. Старые варианты
оставлены для существующих миссий и loadout. Геометрия и материалы не меняются.
Конечное положение хранится живым playback; постоянный кадр больше не нужен.
Обновление проходит через AnimDB, общий для модели и физических частей.

Сервер отправляет команду при смене движения, а подключающимся игрокам —
текущий клип, направление и время без повторного звука. Однопользовательский
клиент использует тот же Common-объект, поэтому не запускает клип второй раз.
Состояние сбрасывается при выгрузке системы; сохранение позы в savegame не добавлено.
В коопе требуются обновлённые клиент и сервер: обычные пакеты активации остались
прежнего формата, именованные анимации используют дополнительную часть пакета.

## Сюжетная команда

```ini
Act_Animation = object_nickname, sc_door_open
Act_Animation = object_nickname, sc_door_close
```

Команда поддерживает существующий объект класса Solar и имя клипа из его модели.
Объект разрешается штатным механизмом имён миссии. При занятом объекте команда
игнорируется с диагностикой: нет перезапуска и накопления очереди. Допустимы
конечные клипы длительностью до часа; вечные клипы отклоняются.

На автоматической двери команда открытия/закрытия получает управление до конца
клипа, затем сканер возобновляет работу. Проигрывание другого клипа временно
выводит дверь из автоматики: вернуть её можно `Act_Animation` с её `anim_open`
или `anim_close`. Для полностью сюжетной двери не включайте `proximity_door`.

Миссионные INI и шаблоны установщик не редактирует.

## Проверка и установка

```powershell
python tools/doors/check.py
python tools/doors/install.py
python tools/doors/install.py --apply
```

Проверки исполняют исходный серверный менеджер и Common playback с тестовыми
объектами/движком, а также настоящие функции кодирования локального и сетевого
пакета с тестовым потоком. Проверяются повторные команды, возврат при закрытии,
задержка и радиусы, позднее подключение, владение со стороны сюжета, ошибочные
клипы, отсутствие привязанных каналов, очистка, усечённые пакеты и сохранность
исходных ресурсов. Эти проверки не заменяют визуальную проверку и пролёт через
створки в игре, а также проверку двух настоящих клиентов в коопе.

Установщик требует закрыть Freelancer и FLServer, проверяет хеши, создаёт
резервную копию и откатывает копирование при ошибке. Шейдеры не меняются.
