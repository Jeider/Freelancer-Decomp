# HUD-плагины: вид цели, вид статуса, вид корабля в инвентаре

[English](../hud_plugins.md) · **Русский**

Три возможности порта, перенесённые из набора плагинов HudInventory RC1 (`HudTarget.dll`,
`HudStatus.dll`, `HudInventory.dll` — Delphi-DLL, которые патчат retail `freelancer.exe` в
памяти). Сами DLL порт загрузить не может: они пишут по жёстко заданным retail-адресам
(`0x004e1f91`, слот vftable `0x005d85f4`, …), где в нашем `freelancer.exe` лежит другой код.
Поэтому их поведение декомпилировано (retail-ссылки, байты патчей и места хуков; для третьего —
сверено с исходником `HudInventory.dpr`) и заново реализовано в `src/freelancer/Client`.

Все три в основном **включают код, который в retail-клиенте есть, но никогда не выполняется**:
вид цели вне режима цели, пустой слот вида HUD_Target_Base у HUD_Status и контролы вида
корабля в инвентаре, которые `NN_Inventory` ищет по имени, но не создаёт.

| Свойство (`src/Freelancer.Diagnostics.props`) | Define | По умолчанию в листе |
|---|---|---|
| `FreelancerHudTargetView` | `FREELANCER_HUD_TARGET_VIEW` | 1 |
| `FreelancerHudStatusView` | `FREELANCER_HUD_STATUS_VIEW` | 1 |
| `FreelancerHudInventoryView` | `FREELANCER_HUD_INVENTORY_VIEW` | 1 |

`src/Directory.Build.props` задаёт 0 для проектов без листа; `/p:<Имя>=0` собирает retail-
поведение. Со всеми тремя в 0 клиент идентичен master.

## Target HUD (`HudTarget.dll`)

Плагин — шесть байтовых патчей без собственного кода:

| Место в retail | Патч | Порт (`FREELANCER_HUD_TARGET_VIEW`) |
|---|---|---|
| `0x004cfe75` HUD_ContactList, двойной клик по строке | `PUSH 1` → `PUSH 0` | `SetMode(0)`: остаёмся в списке контактов (`hud_contact_list.cpp`) |
| `0x004e3ce0` `FUN_004e3c90` (Slot14, каркасный вид) | `JNZ` → 6×`NOP` | вид рисуется в любом режиме, а не только в режиме 1 (`hud_target_panel.cpp`) |
| `0x004e1f91` HUD_Target Update | `JZ` → `NOP NOP` | три кнопки-переключателя обновляются каждый кадр |
| `0x004e203e` / `0x004e20ff` HUD_Target Update | `JZ` → `JMP` | оба блока смены режима пропускаются: данные цели остаются рядом со списком |
| `0x004e36da` `OnMoveFinished` | `OR` → `XOR` | вторая запись в `SwitchToTarget` сбрасывает флаги: кнопка скрыта |

Итог: развёрнутая панель цели показывает каркас цели, имя, подцель и ранг одновременно со
списком контактов или строя.

## Status HUD (`HudStatus.dll`)

Плагин записывает свою функцию в слот 14 HUDItem-vftable HUD_Status (`0x005d85f4`, пустой
`FUN_00401e90` из HUD_Target_Base). Порт переопределяет `HUD_Status::Slot14`
(`hud_status_core.cpp`): при включённой игровой опции `0xa` («HUD») сохраняет viewport,
наводит камеру вида на объект панели статуса (корабль игрока; фиксированная орбита, сдвиг
-0.0125), перекрашивает кэш частей по повреждениям и рисует его — ветка кэша частей из
собственного Slot14 HUD_Target без каркасной сферы, развёртки сканера и рамки подцели.

## Вид корабля в инвентаре (`HudInventory.dll`, бета-клиент)

Переключатель в инвентаре (`ShipView_Toggle`, подсказки IDS 3026 «Ship View» / 3027 «Ship
Inventory») заменяет список предметов кораблём. Плагин воссоздавал режим, который реально есть
в бете `freelancer.exe` от 16.09.2002; поведение вида корабля перенесено из бета-`ShipViewControl`
(vftable `0x005cc0fc`: Update `0x0057a9b0`, Draw `0x0057a390`, MouseEvent `0x0057a860`, выбор
`0x0057bef0` / `0x0057c1e0`, маркеры `0x0057c520` / `0x0057ca30` / `0x0057ce00`). В retail
состояние этого кода осталось — наведение `+0x4f0`, выделение `+0x4fc..+0x508`, биты 4 / 5
`ViewFlags` и цвет `+0x4c4`, — и `NN_Inventory` его по-прежнему заполняет; удалён только код,
который его читал.

- смонтированные предметы текущей страницы фильтра подкрашены `rect_color`; предмет под курсором
  пульсирует, выбранный — жёлтым `+0x4c4`;
- свободные точки крепления показаны маркерами `mountpoint.3db`: без выбранного предмета — точки
  страницы; с выбранным — точки, куда он встаёт, и серые точки страницы, куда не встаёт; маркер
  под курсором пульсирует, а наведение на подходящий играет `ui_select_item`;
- подсказка показывает название предмета, тип точки крепления или «Weapon / Equipment Hardpoint
  (empty)» (IDS 1078 / 1079);
- клик по оборудованию выделяет его и находит его строку на всех страницах фильтра (`0x15`,
  `NnInventory::PickShipViewHardpoint`); клик по подходящему маркеру ставит туда выбранный
  предмет (`0x16`);
- добавляются подпись с именем, рамка, полоса повреждения корпуса и кнопка инфокарты (позиции —
  из плагина: раскладка окна в бете другая);
- от плагина оставлено: у корпусов радиусом больше 30 выбор идёт по началу координат предмета, а
  не по сферам частей, досягаемость точки крепления растёт с корпусом, а с радиуса 80 мелкое
  оборудование рисуется увеличенным.

Код: `NnInventory::CreateShipViewModeControls` / `UpdateShipViewMode` / `PlaceShipView` /
`PickShipViewHardpoint` (`nn_inventory.cpp`), `ShipViewControl::UpdateInventoryHover` /
`DrawInventoryEquipment` / `PlaceInventoryMarkers` / `PickInventoryEquipment` /
`PickInventoryHardpoint` / `MouseEvent` / `ApplyInventoryModelOverride`
(`ship_view_control.cpp`). Хук видимости строк разделяет два retail-флага скрытия (`[ESP+0x10]` /
`[ESP+0x11]` в `FUN_0047f3e0`). Новое поведение получает только собственный `ShipView_Control`
инвентаря; одна часть, как и в плагине, действует на все виды кораблей: фиксированная дистанция
камеры 14 в `SetInstance` пропускается (правка Adoxa `74 → EB` по `0x005855c0`), и каждое превью
вписывает корпус целиком.

### Данные

- `DATA\INTERFACE\NEURONET\INVENTORY\gotoinven.3db` — вторая модель переключателя (обязательна;
  из `DATA` плагина). Маркер — стандартный `mountpoint.3db` (тот же, что в бете); замена из
  плагина тоже подходит, с `mountpoint_size = 0.7`.
- `DATA\INTERFACE\HudInventory.ini` (необязателен), читается один раз при первой отрисовке:

  ```ini
  [HudInventory]
  debug = false          ; true: перечитывать файл при каждом открытии инвентаря
  mountpoint_size = 1.2  ; только порт: масштаб маркера (бета 1.2; 0.7 для меша плагина)
  ship = SHIPS\RHEINLAND\RH_BATTLESHIP\rh_battleship.cmp, center, 0, -70, 0
  ship = SHIPS\RHEINLAND\RH_GUNSHIP\rh_gunship.cmp, radius, 80
  ```

  `center, x, y, z` сдвигает корпус внутри превью, `radius, r` (r ≥ 1) задаёт радиус для
  кадрирования и выбора. Ключ — путь к `.cmp` корпуса (`CreateID`, без учёта регистра).

Файлы мода сторонние и в репозиторий не входят.

## Отличия от плагинов и беты

- Вид корабля следует бете, а не плагину: выбирать можно оборудование любой страницы; подсветка —
  жёлтый `+0x4c4` вместо синего и янтарного плагина; досягаемость точки крепления 0.9 вместо
  0.45; маркеры рисуются с флагами рендера 0 в масштабе беты, оборудование — без синего
  ambient плагина.
- Из беты не перенесены: отрисовка каркаса и рамки (биты 3 / 2 `ViewFlags`, которые retail
  убрал у всех видов кораблей) и сообщение `(0x26, this, hover)` по правому клику, которому не
  соответствует ни одна кнопка retail-`NN_Inventory`.
- `PickShipViewHardpoint` читает режим торговли дилера; плагин читал `+0x978` самого
  инвентаря — за концом обычного `NN_Inventory` (0x974 байта).
- Правка модели ищется по пути, который загрузил `ShipViewControl::LoadMesh`, а не по записи
  архетипа движка у кадрированного экземпляра (это та же строка), и применяется только пока в
  кадре сам корпус.
- `stricmp` по именам точек крепления считает отсутствующее имя пустым вместо падения.
