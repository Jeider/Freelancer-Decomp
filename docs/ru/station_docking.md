# Стыковка с ядром составной станции

Выбираемая модель станции без собственных доков может содержать `base = имя_базы`.
F3 на ней направляет штатную процедуру стыковки к первому объекту текущей системы,
у которого `dock_with` совпадает с этой базой и есть стыковочные хардпоинты.
Поиск идёт в порядке базы объектов, а не по расстоянию. Конкретный причал внутри
выбранного объекта по-прежнему назначает штатная очередь стыковки.

Потсдам уже содержит нужную связь: `rh_ber_04` → `rh_ber_04_dock`.
То же работает для других солнечных объектов с такой связью. Корабли и декорации
без `base` не переадресуются. Объекты с собственными доками сохраняют прямую
стыковку; у планет сохраняется поиск docking ring. Планировщик маршрутов тоже
учитывает станционные ядра. Нового ключа `base_with` не требуется.

В `[Solar]` поддерживается `docking_request_range = 3000`: дистанция, на которой
автопилот завершает начальное сближение и переходит к запросу стыковки. Допустимы
1000–9000 м, по умолчанию 1000 м. Это не радиус коллизии и не финальная точность
стыковки. Метаданные хранятся отдельно от бинарной структуры Solar.

Для `cambridge_shipping_core` (Гринвич, `br_cam_07`) установлено 3000 м: порт
смещён на 1180 м от центра. Настройка сохраняется в сборщике
`tools/station_shipping_core.py`; Pythonlancer не запускается установщиком.

Проверки: `tools/check_station_docking.py` (реальный резолвер, чтение INI через
собранный Common, наследование, недопустимые значения), физика и восемь свободных
подходов Гринвича, независимые анимации восьми доков. Полный полёт и F3 в игровом
клиенте требуют ручной проверки после перезапуска.
