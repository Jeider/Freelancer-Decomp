## Охват и границы проверки

В `DATA/SHIPS` обнаружены 201 CMP и 638 файлов 3DB. Ещё 3 CMP и 3 файла 3DB
добавлены по прямым ссылкам активных ship/simple INI за пределами этой папки.
Итого **845 файлов**, из них 844 разобраны как UTF-модели; один файл с расширением
3DB имеет другой формат. Все 204 CMP и 7 самостоятельных 3DB из ship-архетипов
просмотрены в двух нейтральных ракурсах. Остальные 3DB разобраны структурно;
визуальная проверка каждого damage cap в разрушенном игровом корабле не проводилась.

Прочитаны **2907 анимационных каналов** в **147 файлах**: 2906 scalar и один
quaternion. Найдены 1281 Fix, 692 Rev, 641 Pris и одна Sphere-конструкция.
Учтены все ключи и времена, не только первый/последний кадр. Геометрия всех LOD
прочитана; итоговые суммы по уровню используют последнюю доступную детализацию
каждой части. Это инвентаризация геометрии, не воспроизведение всей логики
выбора LOD движком.

У двух damage cap (`bw_nmd_dmg_engine01.3db`, `bw_pir_dmg_engine01.3db`)
найдены ссылки на отсутствующую внутри файла VMesh-библиотеку; их суммы
геометрии неполные и отмечены в карточках. Пустые VMeshRef с нулевыми счётчиками
у служебных частей Nomad2 отдельно обозначены как placeholders.
Ещё восемь wireframe-ссылок не находят VMesh-библиотеку внутри своего файла
(`polygon.cmp` и шесть заглушек крыльев Bretonia gunship). Это отмечено как
неразрешённые локальные ссылки; наличие библиотеки в глобальном кэше другой
сцены этим проходом не устанавливалось.

Для 812 SUR выполнен структурный проход. Из них 810 имеют поддерживаемый
заголовок версии 2.0; два старых файла отмечены отдельно. В прочитанных данных
2030 частей и 21373 листовые оболочки. Проверка индексов и границ не заменяет
проверку выпуклости, качества контактов и движения физики в игре.

Материалы сопоставлены с библиотеками DATA и встроенными определениями кораблей.
При повторяющемся CRC перечислены варианты: это не заявление о порядке их
загрузки в каждой сцене. 14 неразрешённых ссылок отмечены в карточках.

Все 59 артов просмотрены на обзорных листах. По каждому сохранено наблюдение.
Нет неподтверждённого утверждения, что любой файл текущей DATA — чистый retail,
или что каждый ранний рисунок был воплощён в игре буквально.

## Главный вывод для редизайна

Исходные корабли используют немного крупных узнаваемых масс и механически
осмысленное разделение. Улучшение должно делать эти массы выразительнее и
согласованнее. Деталь, не поддерживающая силуэт, соединение или функцию, не
получает приоритет над формой кабины, корпусом, крылом или настоящим интерьером.

Пример `rh_alt_elite` показывает, что существенный новый образ возможен при
умеренной геометрии: 1832 треугольника против 1514 у `rh_elite`, но изменены
крылья и их схема движения. Это **не лимит** для B; пользователь разрешил больше
геометрии ради близости к арту, при сохранении ограничений CMP/DirectX.

## Повторный запуск исследования

Из корня репозитория, без запуска игры и без записи в DATA:

```powershell
python -B tools/procedural_ships/full_ship_audit.py --render
python -B tools/procedural_ships/ship_collision_audit.py
python -B tools/procedural_ships/ship_motion_preview.py
python -B tools/procedural_ships/art_catalog.py
```

Результаты содержат пути и SHA-256 источников. При обновлении DATA нужно
пересобрать каталог и пересмотреть выводы, затронутые изменениями; текстовый
анализ артов и механики не обновляется автоматически от запуска сканера.

Проверка результата: 854 Markdown-файла, битых ссылок нет; повторно сверены
SHA-256 1716 исходных моделей, SUR и артов — изменений нет.
