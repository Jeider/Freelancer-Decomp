# Сюжетный сервер и запуск кампании

В настройках `FLServer.exe` есть галка «Сервер для сюжетной кампании».
По умолчанию выключена, включая старый `FLServer.cfg`; сохраняется в конфигурации
и учитывается при запуске с `/C`. Режим выбирается до старта сервера.

На работающем сюжетном сервере откройте меню **«Кампания...»**. Окно показывает
общий уровень, состояние кампании и список всех 14 частей: Mission_01a, Mission_01b,
Mission_02 … Mission_13. Выберите доступную миссию и нажмите «Запустить миссию».
Пройденные и будущие миссии видны, но пропускать последовательность нельзя.
Если у подключённых игроков ещё есть активные задания, сначала нужно их завершить.

## Автоматический и ручной запуск

Первая миссия запускается сама после появления первого игрока на базе или в космосе.
Штатные непрерывные переходы Story также остаются автоматическими:

- Mission_01a → Mission_01b;
- Mission_06 → Mission_07;
- Mission_09 → Mission_10 → Mission_11 → Mission_12 → Mission_13.

После Mission_01b, 02, 03, 04, 05, 07 и 08 сервер переходит в свободную игру.
Накопление денег больше не запускает следующую миссию: её запускает хозяин сервера
через окно кампании. После Mission_13 остаётся свободная игра.

Общий уровень вычисляется по этапу Story и применяется ко всем игрокам, включая
поздно подключившихся. Экономика и сторонние вызовы SetRank не могут его повысить.
После обеих частей Mission_01 уровень равен 3, при старте Mission_02 — 4.
Уровень, этап и переходы принадлежат серверу; личный StoryInfo их не перезаписывает.
Общая касса и денежный порог команды пока не реализованы.

## Хранение прогресса

`bin/campaign_progress.bin` рядом с FLServer.exe содержит пройденные части,
фазу кампании, главу, общий уровень и идентификатор попытки. Файл записывается
атомарно и проверяется при чтении. Повреждённое сохранение или ошибка записи
останавливают продвижение; прогресс не сбрасывается молча.

После рестарта во фрифлайте сервер остаётся во фрифлайте. Если был сохранён
автоматический переход, он продолжится после входа игрока.
Если рестарт произошёл внутри миссии, она помечается как прерванная.
«Запустить заново» начинает её с начала с подтверждением: текущий мир и триггеры
в середине миссии не восстанавливаются, сюжетные выдачи могут повториться.
Это контрольная точка последовательности кампании, а не сохранение всего мира.

Новая попытка получает отдельный идентификатор в ключе сохранения local-триггеров.
Внутри одной попытки переподключение сохраняет персональный ход триггеров;
повторный запуск не использует завершённые триггеры прежней попытки.
Файл прогресса нужно включать в резервную копию вместе с персонажами.
Установщик бинарников его не изменяет. При первом обновлении старого сервера
без этого файла последовательность начинается с Mission_01a: миграции из личных
StoryInfo нет.

## Вход в кампанию и ограничения коопа

CampaignLauncher создаёт один CampaignStory при старте сервера, чтобы загрузить
прогресс до выбора персонажа. MissionStart отправляется только после выбора
готового игрока. Повторные входы не создают дополнительную кампанию.
Участники без другой активной миссии присоединяются к общей; после завершения
освобождаются также игроки, не состоящие в обычной группе.

Пока Mission_01a ещё не пройдена, новые персонажи стартуют без корабля на
`sig13_01_base` в `sig13`, комната Deck. Деньги и внешность берутся из MP-шаблона;
корабль выдаёт Аларик. После Mission_01a новые персонажи используют обычный
MP-шаблон с кораблём: без первой миссии получить его у Аларика уже нельзя.
Существующие персонажи не перемещаются, их корабли не удаляются.

В m01a на сюжетном сервере начальный MSN_START заменяется на real_mission_init.
Космическое интро пропускается; после MissionStart синтетическое BaseEnter
регистрирует intro_land.ini до входа в Deck, без перезагрузки игрового мира.
Посадочная сцена, разговор с Алариком и выдача корабля используют персональные
банки участников, включая поздний вход; см. [m01a_scopes.md](m01a_scopes.md).
Изменять шаблоны Pythonlancer для серверного управления не требуется.

Между миссиями ведущим может стать другой готовый игрок. Переназначение ведущего
внутри выполняемой миссии ещё не реализовано: его выход или смена персонажа
приостанавливает обработку миссии, защищая от обращения к устаревшему состоянию.
Командный взлёт, ожидание при переходах между системами и респавн рядом с командой
остаются отдельными задачами. Глобальные сюжетные действия пока не становятся
групповыми автоматически.

## Изоляция режимов

При выключенной галке кампании сервер работает как обычный MP, без общего уровня
и автозапуска сюжета. В одиночной игре сохраняются штатные StoryLauncher/Story,
денежные пороги и личные сохранения. Записи StoryLauncher/CampaignLauncher в INI
для MP пропускаются: запуском управляет галка.

execution_scope = local включает персональные банки только на сюжетном сервере.
В SP и обычном MP триггеры обрабатываются прежним движком. Глобальный scope остаётся
значением по умолчанию.

## Проверка и установка

`python tools/train_courier/check_campaign_server.py` запускает проверки режима,
первого появления на базе, всех переходов кампании, native-элементов окна,
очереди команд, общего уровня, сохранения прогресса, повторных попыток и local-триггеров.
Дополнительно проверяются экспорты и загрузка собранных Server/Content с
зависимостями рабочей игры. Контроллер тестируется с имитацией игроков;
полное прохождение двумя реальными клиентами этими проверками не заменяется.

Сборка: `python tools/train_courier/build.py Server Content FLServer`.
Подготовка пакета: `python tools/train_courier/install_campaign_server.py`.
Установка: та же команда с `--apply`, при закрытых игре и сервере.
Пакет содержит FLServer.exe, Server.dll, Content.dll и их PDB; резервные копии —
`out/campaign_server/backups`. Устанавливается в `D:/Games/FL_MOD/bin`.
Для этого управления кампанией обновление клиентов не требуется.

Проверка и установщик также поддерживают `--with-client` для отдельного обновления
пропуска катсцен: тогда добавляются freelancer.exe/PDB. Esc → Enter завершает
локальную сетевую кинематографическую сцену с RTC-уведомлением, не выбирая ответ
на предложение задания. Именно клиентское обновление пропуска катсцен необходимо
установить каждому игроку.
