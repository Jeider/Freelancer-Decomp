# Переключатель сюжетного сервера

В настройках `FLServer.exe` добавлена галка «Сервер для сюжетной кампании».
По умолчанию выключена, в том числе при чтении старого `FLServer.cfg`.
Значение сохраняется в расширении конфигурации и учитывается при запуске с `/C`.
Режим выбирается до старта сервера; переключение работающей сессии не предусмотрено.

При включении сервер создаёт один `CampaignLauncher`. При первом входе игрока
на базу, до входа в комнату, либо появления его корабля создаётся общий `CampaignStory`,
который запускает `Mission_01a`. Последующие игроки без другой активной миссии
присоединяются к текущей миссии. Повторные события входа не создают второй сюжет.
Персональные блоки `StoryInfo` и `Mission01aSave` не перезагружают общий сюжет.
Записи StoryLauncher/CampaignLauncher в INI для MP пропускаются: запуском управляет галка.

При выключении сервер работает без автозапуска кампании. В одиночной игре
сохраняется штатный StoryLauncher/Story и обычная обработка триггеров.
`execution_scope = local` включает персональные банки только на сюжетном сервере;
без этого режима триггер обрабатывается штатным движком. Глобальный scope остаётся
значением по умолчанию.

Дополнение 13.11: новые персонажи сюжетного сервера создаются на `sig13_01_base`
в системе `sig13` (стартовая комната базы — Deck). Корабль и оборудование из
MP-шаблона не выдаются: первый корабль выдаёт Аларик при принятии задания.
Деньги и внешность по-прежнему берутся из MP-шаблона. Существующие сохранения
не переносятся, уже имеющиеся корабли автоматически не удаляются.
В `m01a` только для сюжетного сервера начальный `MSN_START` заменяется на
`real_mission_init`: космическое интро и вопрос о его пропуске не запускаются.
CampaignLauncher сразу запускает CampaignStory адресованным сообщением после
GameSupport/BaseEnter. После MissionStart на Сигме миссия получает одно
синтетическое BaseEnter, чтобы зарегистрировать `intro_land.ini` до первого Deck.
Это событие не отправляется движку и не перезагружает мир. Повторный MissionStart
не перезапускает сцену. Если ведущий загрузил сохранение на другой базе, триггер
ждёт настоящего прибытия на Сигму. В SP начальный триггер остаётся прежним.

Это первый этап запуска, не готовая кооп-кампания. Персональные посадочные сцены,
Аларик и выдача корабля на Сигме-13 теперь обрабатываются отдельными банками
участников, включая поздно присоединившихся; см. [m01a_scopes.md](m01a_scopes.md).
Адаптер находится в Content и не требует изменений шаблонов Pythonlancer.
Общего сохранения
кампании между перезапусками сервера, смены ведущего и командного взлёта пока нет.
После перезапуска создаётся новая общая миссия; персональные сохранения local
могут остаться от предыдущего запуска. Для независимых прохождений ещё нужен ID сессии.
Существующие глобальные действия сюжетки не стали автоматически групповыми.
Первый участник остаётся ведущим. Первая миссия защищена от обращения к его
устаревшему состоянию после выхода и от подмены персонажа в том же слоте.

Проверки: `python tools/train_courier/check_campaign_server.py` проверяет
сохранение настройки, старую/повреждённую конфигурацию, отсутствие host-export в SP,
однократный запуск и присоединение, изоляцию local-триггеров, сохранение экспортов
и загрузку собранных Server/Content с текущими зависимостями рабочей игры.
Проверки контроллеров используют имитацию игроков; проход двух реальных клиентов
и визуальная проверка новой галки ещё не выполнены.

Сборка: `python tools/train_courier/build.py Server Content FLServer`.
Подготовка установки: `python tools/train_courier/install_campaign_server.py`.
Установка: та же команда с `--apply`, при закрытых игре и сервере.
Пакет содержит только FLServer.exe, Server.dll, Content.dll и их PDB;
резервные копии хранятся в `out/campaign_server/backups`.

Для обновления пропуска катсцен проверка и установщик поддерживают `--with-client`:
в пакет добавляются freelancer.exe/PDB. Подтверждённый Esc -> Enter разрешён
для локально проигрываемых сетевых кинематографических сцен. Используется штатное
завершение последовательности с RTC-уведомлением; ответы на предложения задания
не выбираются автоматически. Это исправление требует обновить клиент у игроков.
