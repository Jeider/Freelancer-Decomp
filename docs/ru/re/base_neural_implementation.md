# DLSS NR в интерьерах: реализация и сборка

Состояние на 8 ноября 2026: реализован экспериментальный движковый путь через DX11 и отдельный x64-помощник. Рабочая установка игры не изменена. Это первый работающий этап проекта: GPU-транспорт и DLSS NR проверяются на стенде; качество лиц в игровых разговорах и влияние DX11-обёртки на космические сцены требуют отдельного игрового прогона.

## Флаг сборки

`FreelancerDlss5=0` — значение по умолчанию. Клиент не компилирует `base_neural_render.cpp`, RP9 не реализует `IRPBaseNeural`, вызовов адаптера нет. Для включения нужны одновременно `/p:FreelancerRp9=1 /p:FreelancerDlss5=1`.

```powershell
python tools/base_neural/build.py --enabled 0
python tools/base_neural/build.py --enabled 1
```

Две сборки находятся отдельно: `out/base_neural/off/bin` и `out/base_neural/on/bin`. Свойство также доступно в `src/Freelancer.Diagnostics.props`. Внешние компоненты не являются зависимостями выключенной сборки.

## Подготовка включённой версии

```powershell
python tools/base_neural/prepare.py --fetch
python tools/base_neural/fetch_sdk.py
python tools/base_neural/prepare.py
python tools/base_neural/build_host.py
python tools/base_neural/build_bridge.py
python tools/base_neural/build.py --enabled 1
python tools/base_neural/check.py --gpu
python tools/base_neural/install.py --stage
```

`prepare.py` проверяет SHA256 архивов Feeder 0.7.0 и dgVoodoo 2.87.6. ReShade x86/x64, RenoDX и DLL модели берутся из существующей установки `E:/games/freelancer game/FL_MOD/exe`; её файлы не меняются. Путь можно задать через `--reference`. SDK NVIDIA скачивается из фиксированной ревизии с проверкой Git blob hash каждого файла. Эти зависимости остаются в `out/`; бинарники NVIDIA не добавляются в репозиторий.

`install.py --stage` собирает пакет, проверяет результаты GPU-тестов и запоминает хеши текущей игры. Установка готового пакета — `python tools/base_neural/install.py --apply`; целевой каталог только `D:/Games/FL_MOD/bin`. Сначала создаётся резервная копия. Если другой билд изменил бинарники после подготовки, установка останавливается. Откат: `python tools/base_neural/install.py --restore <путь_к_резервной_копии> --apply`. Файлы DATA и сохранения не затрагиваются.

## Регулировка в игре

Нейрорендеринг теперь **выключен по умолчанию** (`enabled=0` в поставляемом
`port.ini`). Галочка рядом с ползунком включает/выключает его с предпросмотром;
подтверждение сохраняет `[BaseNeural] enabled` в пользовательском `PerfOptions.ini`.
Снятие галочки останавливает помощник и освобождает его ресурсы. Сила 0% при
включённой галочке остаётся режимом сравнения с загруженной моделью.

В движок встроены жизненный цикл и настройки, но вычисления по-прежнему выполняют
внешние ReShade/RenoDX/NGX и x64-помощник. При `enabled=0` нейропомощник не запускается;
установленные обёртки D3D9/DX11 и ReShade при этом могут оставаться загруженными.
AMD/Intel/неопознанный адаптер отсекаются по DXGI VendorId до запуска помощника.
Проверка NVIDIA VendorId сама по себе не подтверждает поддержку конкретной модели:
ошибка runtime сохраняет исходную сцену. Физическая AMD пока не тестировалась.
Для сборки без нейронных компонентов сохраняется `FreelancerDlss5=0`.

[Нативная цветокоррекция](color_grading.md) работает независимо от этой подсистемы.

В сборке `FreelancerDlss5=1` в **Настройки → Графика** добавлен ползунок
**Сила DLSS 5 / DLSS 5 strength** (0–100%). На базе изменение применяется сразу:
0% показывает исходную сцену с обычным сглаживанием, 100% — полный результат
максимального профиля. Ползунок регулирует смешивание всего кадра; внутренние
параметры модели, включая обработку окружения и персонажей, остаются прежними.
При нуле модель остаётся загруженной на базе для быстрого сравнения; это не
выключатель вычислений. При вылете сессия освобождается штатным `Stop()`.

Подтверждение сохраняет `[BaseNeural] strength_percent` в пользовательском
`PerfOptions.ini`, отмена возвращает предыдущее значение. Пока значение не сохранено,
используется `blend_strength` из `port.ini`; кнопка настроек по умолчанию также
возвращает это значение. Предпросмотр не попадает в файл при постороннем сохранении.
В сборке с флагом 0 ползунок и код настройки отсутствуют.

Обработчик учитывает, что во внутриигровом меню `Anim` остаётся равным -2:
блокировка на время вступительной анимации применяется только к главному меню.
Это покрыто регрессионной проверкой `check_preferences.py`.

Цвет, глубина и результат передаются в полном разрешении активного кадра
(в проверенной игре — 2560×1440). Служебное окно помощника 960×540 не задаёт
разрешение нейрообработки. Оценка движения использует грубый поиск как начальное
приближение, затем уточняет каждый пиксель и дробное смещение. Копирование одного
целочисленного вектора на блок 4×4 удалено. Это всё ещё оценка по изображению,
а не точные векторы анимации персонажей. `probe_flow.cpp` проверяет движущуюся
текстуру, дробные смещения, нулевую историю и неподвижный кадр на GPU.

Тексты находятся в ресурсах RU/EN и в Pythonlancer `text/static.py`, IDS 238267–238268.
`check_preferences.py` проверяет реальные методы UI с заглушками виджетов, отмену,
подтверждение и загрузку в новом процессе. `check_strength_gpu.py` переключает
0/50/100% в одной сессии настоящего NR и проверяет исходные пиксели при 0% и UI.
Обновление существующей установки: `install_slider.py --stage`, затем `--apply`;
пакет сохраняет резервную копию и проверяет конкурирующие изменения по хешам.

## Настройка игры

### Суперсэмплинг интерьеров

`[BaseNeural] supersample_scale=1.5` включает отдельный буфер цвета и глубины
перед отрисовкой комнаты: на экране 2560×1440 это настоящий рендер 3840×2160.
Нейрообработка получает эти же высокие размеры; после неё выполняется уменьшение
по площади пикселей в линейном цветовом пространстве. Интерфейс рисуется затем
в родном разрешении, координаты камеры/мыши остаются прежними. При прогреве модели
сохраняется суперсэмплинг исходной сцены. Ползунок силы 0–100% продолжает работать.

Для отключения установить `supersample_scale=1.0` и перезапустить игру.
Допустимый масштаб 1–2; в этой экспериментальной версии размер выше 3840×2160
или неподдерживаемая поверхность оставляют обычный рендер. Ресурсы комнаты
освобождаются на вылете и при сбросе устройства. В космосе и главном меню этот
буфер не используется. Флаг сборки `FreelancerDlss5=0` исключает весь механизм.

Интерфейс клиента/RP9 изменён на `IRPBaseNeural_v2`: устанавливать обе сборки
вместе. `check_supersample.py` проверяет точное усреднение полос толщиной один
пиксель, восстановление буфера/viewport, отменённый кадр, native UI и настоящую
обработку NR 3840×2160. Тестовая задержка NR на RTX 5080 составила около 46 мс;
это не замер FPS полной игровой сцены. Визуальное сравнение персонажей требуется
в самой игре. Пакет: `install_supersample.py --stage`, затем `--apply`.

В `bin/port.ini`:

```ini
[BaseNeural]
enabled=0
mode=2
result_deadline_ms=250
blend_strength=1
supersample_scale=1.0
```

`enabled=0` отключает запуск NR при следующем старте игры; `port.ini` кешируется. `mode=1` проверяет передачу исходного кадра без нейронной обработки, `mode=2` включает DLAA/NR. `blend_strength` задаёт долю результата от 0 до 1; смешивание выполняется в линейном пространстве. `result_deadline_ms` ограничен диапазоном 1–250 мс. При пропуске срока сохраняется оригинал и сессия завершается до следующего посещения базы. Первые четыре кадра прогреваются асинхронно, их устаревший результат никогда не показывается.

Стиль модели задаётся отдельно в `bin/neural/host64/ReShade.ini`, секция `[RenoDX.DLSS5]`. Профиль полной силы: `NRIntensity`, `NRGlobalTone`, `NRLocalTone`, `NRLocalStructure` равны 2; `NRSkinStructure=1` (исправлено прежнее значение 2 вне диапазона панели Feeder). `NRAutoMask=0`, `NRUICorrection=0`, цвет и transfer strength равны 1. Вся сцена обрабатывается в нативном разрешении, игровой UI рисуется после неё. Paper white и масштаб motion vectors — калибровки, для SDR и пиксельных векторов стоят 1. Пресет и стиль сохранены из проверенной установки: их номера не являются уровнями качества. Профиль применяется через `tools/base_neural/max_profile.py --apply`, с резервной копией, без автоматического включения нейрообработки. На стенде холодный запуск занимал десятки секунд; всё это время доступен обычный интерьер. Таймер прогрева не блокирует главный поток игры.

Панель и уведомления ReShade скрыты. Стартовая плашка подавляется в add-on callback перед сборкой draw data; её пустые команды не отправляются на GPU. `probe_overlay.cpp` проверяет первые 20 готовых кадров после UI ReShade. Игровой интерфейс эта обработка не затрагивает.

## Где выполняется обработка

Разрешение на обработку выдаётся только вокруг `DrawClientLocation()` в игровом кадре базы. Intro/menu и техническая пересадка курьера этот допуск не получают. Захват находится после отрисовки комнаты и до обычного AA, HUD, окон, курсора и fade. После успешного NR дополнительный пространственный AA не применяется; при прогреве и ошибке работает прежний путь.

RP9 заканчивает текущую D3D9-сцену, вызывает зарегистрированный DX11-адаптер и возобновляет сцену. Адаптер сохраняет и восстанавливает D3D11 context state. Цвет и глубина копируются в собственные ресурсы. Motion vectors пока оцениваются по двум исходным кадрам; это начальный optical-flow provider, а не нативные векторы костей персонажа. История сбрасывается при смене базы, комнаты, камеры, скачке позиции/ориентации/FOV и разрыве кадров.

Хелпер строится из зафиксированного MIT-исходника Feeder с проверяемыми изменениями. У него отдельные имя EXE, pipe, magic и версия протокола. Каждый кадр получает явное подтверждение успеха; синхронизация ресурсов дополнительно проверяется GPU fence. Идентичность клиентского и серверного процессов проверяется. Ожидание GPU ставится только после доказанного завершения fence, поэтому погибший помощник не оставляет вечное ожидание в очереди игры.

`LeaveClientLocationBase`, потеря/пересоздание устройства и выключение рендера останавливают сессию. Job Object завершает помощник, в том числе при аварийном завершении игры. Собственные shared textures, optical-flow history, fences и обработчики освобождаются. В космосе адаптер не подписан на обработку кадров, эффекты ReShade и Launchpad не запускаются.

При этом **dgVoodoo и сам слой ReShade остаются загружены для DX11-устройства на протяжении процесса**. Выключение NR не превращает его обратно в нативный D3D9. Полный возврат к исходному графическому пути требует отката компонентов; отсутствие регрессии FPS в космосе пока не заявляется.

## Проверки и практические ограничения

`check.py` проверяет наличие интерфейса в обеих включённых сборках и его отсутствие в обеих выключенных. GPU-прогоны выполняются в скрытом окне на RTX 5080: побитовое совпадение исходного кадра, полный D3D9/DX11/x64 обмен, сохранность UI поверх результата, DLSS NR в 2560×1440, убийство помощника и многократная отмена запуска. NR считается подтверждённым только при строке `inline feature 18 evaluation succeeded` в журнале. Результаты и журналы сохраняются в `out/base_neural/checks`.

Поддерживаются обычные SDR RGBA8/BGRA8 targets без MSAA, глубина D24S8 и D32F. Неподдерживаемая поверхность оставляет оригинальную сцену. HDR, нативные skeletal motion vectors, маски лиц/рук, визуальная оценка диалогов, игровые Alt-Tab/resize и A/B-производительность в космосе ещё не проверены/не реализованы. Рендерер специально остаётся выключенным в стандартной сборке до этих проверок.

Технический проект и последующие этапы: [base_neural_rendering_design.md](base_neural_rendering_design.md).
