# Поиск трейдлейнов по типу архетипа

В `Content/SystemInfo.cpp`, `FSystemInfo::LoadFromReader`, снята retail-проверка
буквального имени `Trade_Lane_Ring`. Теперь `[Object] archetype` разрешается через
`Archetype::GetSolar(CreateID(...))`; кольцом считается объект, у которого в
описании архетипа установлен `ObjectType & 0x80`, то есть `type = TRADELANE_RING`.
Пустые/неизвестные архетипы не добавляются. Само имя `Trade_Lane_Ring` без этого
типа больше не является достаточным условием.

Это путь загрузки описания системы, в том числе `Load(false)` из
`RegisterRmDestSystem`. Здесь нельзя полагаться на поиск живого `SpaceObj`:
случайные миссии рассматривают системы, чьи объекты ещё не созданы. Реестр
архетипов позволяет получить тип без загрузки меша или создания объекта.

Список передаётся в существующий `BuildTradeLanes`, который собирает цепочки
по `prev_ring`/`next_ring`. `FRandomMissionLoader::CollectZonesAlongTradeLanes`
использует эти цепочки при поиске достижимых зон случайных миссий. Путь
`RebuildTradeLanes` для живых объектов уже ищет кольца по типу `0x80`.

Изменение не переносит геометрию, не меняет комплектации, анимации, коллизии,
связи колец, ограничения дальности миссий или выбор прыжковых объектов.
Отдельные ограничения live-сканирования также не менялись. Настройка включена
во всех профилях Content, без зависимости от RPG/RP9.

Проверка: `python tools/tradelane/check_system_types.py`. Исполняются извлечённые
из production-кода обработчик `[Object]` и `BuildTradeLanes` с подменой границы
INI/реестра архетипов. Проверяются смешанная цепочка обычных и произвольно
названных колец, порядок ключей, координаты/вращение/фракция, неизвестные и
пустые описания, ложный положительный результат по имени и прежние jump-объекты.
Это автономная проверка логики; выдача миссии внутри игры ею не проверяется.

Сборка: `python tools/train_courier/build.py Content`.
Подготовка: `python tools/tradelane/install_system_types.py`.
Установка: та же команда с `--apply`; нужны закрытые игра и сервер.
Меняются только `bin/Content.dll` и соответствующий PDB. Установщик сверяет
хеши, сохраняет резервную копию в `out/tradelane_system_types/backups` и
восстанавливает файлы при ошибке установки.
