# Персональные триггеры: первый срез

Дополнение: персональная обработка теперь включается только галкой
«Сервер для сюжетной кампании» в FLServer. В SP и обычном MP используется
штатный обработчик, даже при наличии `execution_scope = local`.
Текущий запуск и установка описаны в [campaign_server.md](campaign_server.md).
Для m01a добавлен ограниченный адаптер личной цепочки Сигмы-13 и трёх однократных
переходов к общим триггерам; подробности в [m01a_scopes.md](m01a_scopes.md).
Ниже приведены сведения о предыдущей установке отдельного Content.

Установлено 12.11.2026 23:32 в рабочий `D:/Games/FL_MOD/bin`: только Content.dll/PDB.
Резервная копия: `out/local_triggers/backups/20261112_233245_475416`.
Сборки Content с RPG=1 и RPG=0 прошли. Новая DLL проверена загрузкой с текущими
зависимостями рабочей игры; реальный проход двух клиентов и сцен пока не проверен.

По умолчанию все существующие триггеры глобальные. Ничего дописывать в них не нужно.
Для отдельного состояния у каждого участника используется только явная отметка:

```ini
[Trigger]
nickname = personal_question
execution_scope = local
InitState = ACTIVE
Cnd_Timer = 1, true
Act_PopUpDialog = 12345, 12346, YES_NO
Act_ActTrig = personal_answer

[Trigger]
nickname = personal_answer
execution_scope = local
Cnd_PopUpDialog = YES
Act_SetShipAndLoadout = your_ship, your_loadout
```

Числа, корабль и loadout здесь условные. Параметры действий остаются штатными.
`execution_scope = global` допустим, но не требуется. Неизвестное значение scope
отклоняет триггер с диагностикой, а не превращает его в глобальный.

## Реализовано

- Одна серверная миссия, отдельные экземпляры условий/действий и состояния локальных
  триггеров для её участников. Вторые Story/контроллеры и миры не создаются.
- Участники: владелец миссии и персонажи, уже присоединённые к её live mission ID.
  Само наличие local-триггера не присоединяет всех игроков сервера к миссии.
- `InitState = ACTIVE` запускается у каждого участника. Поздний участник получает
  собственный начальный набор, уже проходивший — сохранённый прогресс.
- Таймеры и активные/завершённые/неактивные состояния раздельны. `repeatable` остаётся
  независимым свойством: local сам по себе не разрешает повторную выдачу корабля.
- Base/Location/GFObjSelect/RTC/popup события фильтруются по отправителю;
  персональный ответ не проходит в банк другого участника.
- RTC-списки и их runtime handles принадлежат конкретному персонажу. При выходе
  handles освобождаются; незавершённая сцена может быть запущена заново после входа
  на базу. Продолжение анимации с точного кадра не реализовано.
- `[LocalTriggerState]` и `[LocalTriggerRtc]` пишутся через обычный серверный
  PlayerSave и читаются через GameSupport/PlayerLoad. Изменения DATA не нужны.
- Прогресс сохраняется и после уничтожения контроллера в текущем процессе, чтобы
  последующее сохранение персонажа не теряло завершённые локальные триггеры.

## Поддержанные команды

Условия: `Cnd_True`, `Cnd_Timer`, `Cnd_BaseEnter`, `Cnd_BaseExit`, `Cnd_LocEnter`,
`Cnd_LocExit`, `Cnd_PopUpDialog`, `Cnd_RTCDone`, `Cnd_CharSelect`, `Cnd_WatchTrigger`.

Действия: `Act_ActTrig`, `Act_DeactTrig`, `Act_PopUpDialog`, `Act_AddRTC`,
`Act_RemoveRTC`, `Act_SetShipAndLoadout`.

Неподдержанная команда отклоняет весь local-триггер с диагностикой. Глобальные
триггеры сохраняют прежний набор команд. Это ограничение первого среза: пока нельзя
просто пометить любой существующий базовый сценарий local и ожидать полной поддержки.

Цепочки `Act_ActTrig`/`Act_DeactTrig` остаются внутри одного scope. Local → local
относится к тому же персонажу; автоматического перехода local → global или веера
global → local нет. Активация через эту границу отклоняется с диагностикой.
Командные барьеры будут отдельным расширением.

## Переподключение и границы сохранения

Игра хранит не «последний триггер», а набор состояний и данные активных условий.
Например, два параллельных таймера должны восстановиться независимо. Завершённые
начальные триггеры также сохраняются, чтобы повторный вход не запускал их заново.

Первый срез использует уникальное на сервере имя персонажа и путь файла миссии.
Номер слота соединения не является ключом; новый персонаж в старом слоте не получает
чужой прогресс. Переименование персонажа, отдельные ID прохождений и сброс главы
пока не реализованы. Повторное прохождение тем же персонажем того же файла миссии
требует отдельного механизма сброса; автоматически старые отметки не удаляются.

Восстановление — из последнего успешного обычного сохранения персонажа. Здесь нет
транзакционного журнала на каждое действие и гарантии exactly-once при падении
между выдачей корабля и сохранением. Продолжение всей кампании после перезапуска
сервера требует восстановления её общего контроллера и состава участников — этот
модуль этого не делает. При выходе ведущего общий сюжет не передаётся другому
игроку автоматически; предотвращены очистка триггеров на выходе гостя и выполнение
за постороннего игрока, занявшего слот ведущего.

## Проверка

`python tools/train_courier/check_local_triggers.py` компилирует production parser,
scheduler и LocalTriggers.inl с настоящим INI_Reader и подставными игроками/действиями.
Проверяются default global, два участника, личные цепочки/таймеры, повторный ответ,
repeatable, save/load, другой слот при переподключении, чужой слот, завершённые и
неактивные состояния, сохранение после уничтожения контроллера, неизвестный scope
и недопустимое действие. Это не тест двух настоящих сетевых клиентов или RTC-рендера.

Исходники: `src/Content/LocalTriggers.inl`, `LocalTriggers.h`, интеграция в
`MissionScript.cpp` и `GameSupport.cpp`. Существующие миссионные INI не изменены.
