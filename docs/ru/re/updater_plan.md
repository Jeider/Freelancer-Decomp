# Апдейтер

Игрок не получает git. Источник для него — номер версии и список файлов.
Git остаётся только у разработчика. Старый `install.py` и `reset --hard` этим заменяются.

Апдейтер — не вторая программа, а режим того же `NomadLauncher.exe`.
Окно только проверяет версию и показывает кнопку. Подмену делает копия exe,
потому что запущенный файл сам себя не перезапишет.

## Релиз

Публикуется чистое дерево релиза, не живая установка игрока и не репозиторий декомпиляции.
В корне нет `SAVE`, нет `.git`, нет `updates`. Скрипт при их наличии отказывается:
так нельзя случайно залить сейвы или снять снимок с включённым DLSS.

Порядок на машине разработчика:

1. Собрать дерево: `bin\`, нужные `DATA`, лаунчер, `redist`.
   Канонические `dxgi.dll` и `D3D9.dll` лежат в `bin\neural\off`, не в `bin\`.
2. Запустить публикацию: корень, версия `YYYY.MM.DD.N`, коммит.
3. Скрипт считает SHA-256, заливает только новые блобы, проверяет, что каждый хеш читается.
4. Последним шагом подменяет `stable.json`. До этого игроки на старой версии.

Первая установка по-прежнему полный архив. Апдейтер раздаёт разницу.
Хранилище — Cloudflare R2 или Bunny Storage, перед ним CDN.
Лаунчер знает один адрес, например `https://freelancer2.space/updates/stable.json`.
Блобы: `blobs/<sha256>`, кэш навсегда. Манифест кэшируется около минуты.
Отдельный сервер не нужен. Учётные данные публикации только в окружении, не в репозитории.

## Манифест

```json
{
  "version": "2026.11.19.1",
  "commit": "abc123",
  "files": [
    {"path": "bin/freelancer.exe", "sha256": "...", "size": 123456}
  ]
}
```

Пути от корня игры, прямой слэш. Нет записи — файл апдейтеру не принадлежит.

Рядом с игрой `updates/installed.json` — манифест, который реально поставлен.
Удаляются только пути, которые были в нём и пропали из нового.
Первый запуск без этого файла ничего не удаляет: существующая установка
получает файлы релиза поверх, самодельные файлы остаются.

Не трогать:

- `SAVE\`, включая сейвы, `PerfOptions.ini` и `launcher.ini`.
- Всё, чего не было ни в одном манифесте.
- Живые `bin\dxgi.dll` и `bin\D3D9.dll`. После установки галка DLSS
  применяется заново к копиям из `bin\neural\off`.

## Процесс

Обычный запуск рисует окно. Проверка версии идёт в фоне и не блокирует кнопки запуска.
Сеть молчит — игра доступна, строки обновления нет.

Есть разница — кнопка «Обновить». Она не стартует, пока запущены
`freelancer.exe` или `FLServer`. Дальше:

1. Лаунчер копирует себя в `updates/apply.exe`.
2. Запускает `updates/apply.exe --update --root <корень игры>` и выходит.
3. Копия качает недостающее в `updates/staging`, сверяет размер и SHA-256.
4. Пишет журнал. Каждый заменяемый и удаляемый файл сначала уезжает
   в `updates/rollback/<старая версия>/`.
5. Ставит новые файлы. Если хеш не сошёлся, журнал проигрывается назад.
6. Заново применяет DLSS. Пишет `installed.json`.
7. Запускает лаунчер из корня, не игру.

Лаунчер после своего окна помечает старт удачным, и только тогда откат удаляется.
Упал при старте — следующий запуск предлагает вернуть прошлую версию.

Корень игры передаётся аргументом. Каталог `apply.exe` корнем не считается.

## Код, от которого стартуем

Прототип без облака. Источник файлов — локальный каталог с тем же манифестом и блобами.
HTTP и R2 встают позже за тем же интерфейсом «прочитать манифест, отдать блоб по хешу».

В `FLLauncher`:

- `src/main.cpp` — окно. Добавляются строка версии и кнопка «Обновить».
- `src/update.cpp` — манифест, сравнение, план, журнал, подмена, откат, DLSS.
- `src/update.h` — эти типы, без Win32-окна.
- `tools/publish_update.py` — обход дерева, хеши, сборка локального origin.
  Позже тот же скрипт дописывает заливку в хранилище.

Сравнение не сканирует диск в поисках лишнего. План строится из трёх списков:
что скачать (нет файла или другой хеш), что оставить, что снять
(было в `installed.json`, нет в новом манифесте). SHA-256 через BCrypt.
Сеть прототипу не нужна.

Проверка прототипа — на фиктивном дереве, не на живой игре:
файл совпал и не качается, файл изменился и заменяется, чужой файл остаётся,
снятый с манифеста удаляется, обрыв журнала откатывается, живой `dxgi.dll`
не становится файлом релиза, после установки галка снова его выкладывает.

В прототип не входят CDN, beta-канал, дельта внутри файла и подпись манифеста.
Подпись — следующий шаг до первой публичной раздачи, не до первого прогона.
