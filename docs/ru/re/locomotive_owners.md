# Владельцы локомотивов

Отбор идёт по `isinstance(BASE_PROPS, (meta.LargePlanet, meta.Megabase))` в Pythonlancer,
включая наследников. Закрытые базы исключаются. Текущий охват: 19 баз — 13 планет
и 6 станций. Маннгейм входит с экономическим типом LargePlanet.

Источники: `managers/courier_owners.py`, реестр `story/rpg/courier_owners.json`.
Реестр сохраняет стабильные группы rm0200–rm0218, внешний вид и место владельца.
Группы зарезервированы и для генератора комендантов стоянок. Оба генератора учитывают
занятые друг другом места. Существующий контакт Бисмарка используется повторно.

## Разговор

Для получения задания нужна репутация строго больше нуля у фракции местного
владельца. Нулевая репутация тоже означает отказ. Проверка выполняется при
запросе работы и повторно при выдаче задания после выбора вагонов; используется
существующая озвученная ветка `bad_reputation`.

Продажа парковочных мест подчиняется тому же правилу у фракции продавца.
Сервер проверяет репутацию при расчёте предложения и перед списанием денег.
Для отказа добавлена ветка `parking_bad_reputation`: русский и английский текст,
английская озвучка и сцена `frag0023` во всех 55 озвученных группах. Остальные
178 продавцов показывают текст. Уже купленные места остаются доступны.

Общий сценарий и озвучка — rm0001. Индивидуальная группа владельца содержит
`conversation.thn` и `gestures/`, но не копии WAV. Заголовок диалога разделяет
`scene_group` (озвучка), `session_group` (поза, камеры и жесты) и `courier_base`
(разрешённая база выдачи задания). Отдельные голоса в дальнейшем подключаются
через `voice_group` реестра.

12 владельцев стоят, 7 сидят. Используются существующие GestureScene/Autoplay,
включая поддержку сидячего персонажа. Трент стоит; его последовательность не меняется.
Сохраняются взаимный IK, перевод камеры на игрока при выборе, пропуск одной реплики
по Esc и неделимые последовательности жестов. Подхода и вступления с WFC нет.

Все 32 английских фрагмента записаны и подключены всем 19 владельцам. Реплики
0022–0032 (пояснения лицензии и обучение) догенерированы через VoiceStudio в PCM16
WAV 24 кГц; прежние 21 запись сохранены. Русская озвучка пока не записана.
Новую озвучку генератор владельцев не создаёт. Свежие WAV требуют пересчёта сцен; несовпадение
хеша голоса и сцены останавливает подключение.

## Работа и сохранения

Сервер проверяет базу игрока при проверке доступности и при выдаче задания.
Перед созданием миссии проверяются причал, местная грузовая точка, исходящий маршрут
и служебная база пересадки. Контроллер выбирает источник по базе игрока.
Локомотив получает местные координаты, систему, ориентацию и фракцию.

У планет используются существующие причалы. Для мегастанций добавлены недостающие
грузовые точки и отдельные причалы выше станционных конструкций. Экономика берётся
из Pythonlancer, маршруты — из того же графа TradeConnection/jumpgate.
Существующие записи каталога сохраняются. Описание возврата подходит станциям и планетам.

Начальная точка сохраняется уже до посадки, включая промежуточную пересадку.
Старые сохранения до посадки без записанного источника трактуются как Бисмарк.
Активные перевозки продолжают восстанавливаться по сохранённому источнику.

Постоянная лицензия между сменами остаётся отдельной запланированной задачей
из `train_courier_design.md`. Демонстрационный выбор 2/5/10/20 вагонов сохранён.

## Команды

Из каталога Pythonlancer:

```text
python -B single.py rpg owners --dry-run
python -B single.py rpg owners
python -B single.py rpg runtime --group rm0001
```

`owners` сверяет охват с исходным миром, рассчитывает размещение и публикует контакты.
`runtime rm0001` после обновления озвучки переподключает всех владельцев без полной
генерации мира. Обычная генерация мира после включения реестра также обновляет владельцев.
Все записи DATA, резервные копии DATA и откат проходят через DataFolder.

После экспорта `universe.ini` и `mbases.ini` генератор владельцев восстанавливает
служебные базы пересадки `tc_<system>_base` для всех систем каталога перевозок.
Их регистрации, файлы Deck и сценарии выхода `launch_<system>.ini` входят в одну
транзакцию с владельцами. Это работает и для отдельной папки сборки: регистрации
больше не зависят от однократного запуска установщика. Повторный экспорт не
создаёт дубликатов; конфликт системы у существующей базы вызывает явную ошибку.
Регрессионная проверка: `tools/train_courier/check_owners_export.py`.

Установка исходников, подготовка игрового пакета и установка бинарников из репозитория:

```text
python -B tools/train_courier/owners.py sources
python -B tools/train_courier/owners.py apply-sources
<Pythonlancer/.venv/Scripts/python.exe> -B tools/train_courier/owners.py stage
<Pythonlancer/.venv/Scripts/python.exe> -B tools/train_courier/check_owners.py
python -B tools/train_courier/owners.py apply
```

Пакет и отчёт: `out/train_courier/owners/`. Установщик проверяет хеши,
останавливается при запущенной игре или внешнем изменении файлов и сохраняет резервную копию.
Проверяются реальный код выбора причала, все 19 владельцев с 2/5/10/20 вагонами,
раздельные группы звука и жестов, смена базы, повторная выдача, сохранения и откат DATA.
Визуальное положение персонажей и заходы к новым станционным причалам требуют проверки в игре.
