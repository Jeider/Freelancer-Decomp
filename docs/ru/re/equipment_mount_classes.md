# Классы и слоты для брони, сканеров и тракторов

[English](../../re/equipment_mount_classes.md) · **Русский**

Реализовано в рабочем дереве 2026-10-27 поверх `af086d9`. Это отдельная возможность порта, выключенная по умолчанию при сборке и запуске. В первоначальном исследовании предлагались `mount_family`/`mount_class`; реализация использует `hp_type`, согласованный с существующим форматом оборудования. Предложенные ранее ключи и `equipment_slot_hardpoint` **не поддерживаются**.

## Включение

Собрать **Common, Server и freelancer** с параметром MSBuild `/p:FreelancerEquipmentSlots=1` — он определяет `FREELANCER_EQUIPMENT_SLOTS`. В `port.ini` рядом с исполняемым файлом:

```ini
[Equipment]
internal_classes = 1
```

После изменения нужен перезапуск: настройка запоминается при первом обращении. Механика не требует включённого плагина Adoxa engclass; подписи слотов имеют собственные русский и английский варианты. Клиенту и серверу нужны согласованные сборки, настройки и контент. Согласование возможностей по сети и автоматическая миграция сохранений не реализованы. Для сохранений/контента с новыми классами отключать возможность нельзя.

## Описание контента

Ниже фрагменты для добавления в полноценные определения оборудования, корабля и комплектации:

```ini
[Armor]
nickname = armor_plate_class3
hp_type = hp_armor_special_3
hit_pts_scale = 1.20

[Scanner]
nickname = survey_scanner_class2
hp_type = hp_scanner_special_2
range = 7000
cargo_scan_range = 1800

[Tractor]
nickname = salvage_tractor_class3
hp_type = hp_tractor_special_3
max_length = 2200
reach_speed = 500

[Ship]
; Постоянное имя слота, семейство, максимальный класс.
equipment_slot = HpSlot_Armor01, armor, 4
equipment_slot = HpSlot_Scanner01, scanner, 3
equipment_slot = HpSlot_Tractor01, tractor, 3

[Loadout]
equip = armor_plate_class3, HpSlot_Armor01
equip = survey_scanner_class2, HpSlot_Scanner01
equip = salvage_tractor_class3, HpSlot_Tractor01
```

У каждого семейства классы **1–10**. Броня класса 3 подходит в слот брони до класса 4; броня класса 5 и сканер туда не подходят. Класс определяет совместимость, а дальность, коэффициент прочности и скорость трактора — обычные параметры устройства. Для продажи отдельно нужны обычные goods категории equipment, иконки, IDS имени/описания и записи рынка. Сам класс не создаёт товар.

Имена слотов нечувствительны к регистру и должны быть уникальны на корабле, включая обычные hardpoint. Имя грузового отсека использовать нельзя. Неизвестное семейство, неправильный класс и повторный `equipment_slot` записываются в журнал и игнорируются. Неправильный `hp_type` устройства оставляет его невалидным для установки, а не превращает молча в старый встроенный прибор.

Поддерживается также точное указание класса:

```ini
[Ship]
hp_type = hp_armor_special_3, HpSlot_Armor01
```

Это разрешает **только класс 3**, а не классы 1–3. Для диапазона использовать `equipment_slot` либо перечислять все допустимые типы. Не смешивать оба формата для одного слота. Интерфейс показывает высший разрешённый класс; пропуски в точном перечислении всё равно запрещены проверкой совместимости.

Это **логические внутренние слоты**, новые точки в CMP не нужны. Они отображаются строками оборудования с установкой/снятием, без отдельной внешней модели для выбора мышью. Источник луча трактора по-прежнему задаёт существующий `hp_tractor_source` корабля. Объявление слота не создаёт геометрическую точку луча.

## Поведение и ограничения

- На корабле допускается одна установленная броня, один сканер и один трактор. При установке нового классового устройства учитывается и старый встроенный прибор того же семейства. Запасные приборы могут лежать снятыми в трюме.
- Установленное устройство занимает слот; его объём учитывается в трюме после снятия. Для снятия действует обычная проверка свободного места.
- Пустые слоты разрешены. Без сканера переключение следующего/предыдущего врага возвращает отсутствие цели, а автоматика контрмер пропускает поиск угроз по сканеру. Обычное переключение целей уже обрабатывает отсутствие сканера. Без трактора сбор недоступен.
- Устройства остаются `CEArmor`, `CEScanner` и `CETractor`. Новые формулы боя, лечение, режимы сканирования, охлаждение, навыки и бустеры этим изменением не добавляются.
- Имя слота сохраняется через `CInternalEquip::GetEquipDesc` и копирование устройства; уничтожение удаляет привязку. Наследование, копирование, переопределение и уничтожение архетипа обслуживают метаданные класса. Перезагрузка определения без `hp_type` возвращает старый внутренний тип.
- Занятость слота определяется полной комплектацией, а не наличием видимой модели прибора. Покупка, установка и перенос при смене корабля учитывают новые семейства. Если свободного подходящего слота нет, покупка идёт в трюм при наличии места.
- Серверные операции добавления, изменения и загрузки проверяют будущую комплектацию до замены оборудования. При отказе сохраняют прежнюю комплектацию и отправляют её клиенту. Создание устройства в мире тоже проверяет совместимость, включая попытку добавить старый встроенный прибор после нового.
- Покупка корабля проверяет комплектацию на целевом корпусе до изменения денег/товара, затем отправляет новый архетип перед оборудованием: сервер проверяет слоты уже нового корабля. Торговые сообщения остаются раздельными: это **не** атомарная транзакция экономики и не законченная система защиты от читов.

Без нового `hp_type` оборудование сохраняет прежнее внутреннее поведение. Старые корабли автоматически слоты не получают. Для внедрения использовать новые nickname приборов и явно подготовленные корабли/loadout. Если превратить существующий встроенный nickname в классовое устройство, сначала нужно мигрировать старые комплектации/сохранения: неверная установленная привязка отклоняется, а не исправляется автоматически.

Размеры структур архетипов/оборудования, виртуальные таблицы и сетевой формат дескриптора сохранены. Метаданные определения хранятся по адресу архетипа с обслуживанием копирования/уничтожения: отброшенное дублирующее определение nickname не меняет живой архетип. Привязки экземпляров хранятся по адресу устройства с обслуживанием того же жизненного цикла. Параллельный инвентарь и новый универсальный класс устройства не вводятся.

## Проверки и оставшаяся интеграционная проверка

[Нативный тест](../../../tools/equipment_slots/README.md) использует настоящий Common.dll: строгий разбор INI, ограничения семейства/класса/занятости, сосуществование со старыми приборами, установка на CShip и учёт трюма, выбор целей без сканера, сохранение дескриптора, наследование, копирование, очистка метаданных и перезагрузка. Отдельные процессы проверяют runtime on/off; для сборки без возможности предусмотрен отдельный режим.

Локально проверены сборки Common, Server и freelancer в Release/Win32 с включённой и
выключенной возможностью; нативные тесты runtime on/off и compile-off; сборка Common
DebugASan и те же нативные тесты под AddressSanitizer. Ошибок санитайзера не обнаружено.
Логи сборок находятся в игнорируемом каталоге workspace `src/obj/equipment_slots_*`, команды —
в README теста.

Сборка и нативные тесты не заменяют проверку в игровом интерфейсе. На настоящих ресурсах мода ещё нужно пройти торговца оборудованием, пустые/занятые строки и RU/EN подписи, покупку корабля, вылет → посадку → сохранение → загрузку, синхронизацию SP/MP и полёт со снятым каждым прибором. Здесь не заявляется установка контента в игровую папку или интерактивная проверка.

## Дальнейшее развитие

Для охлаждения подходит тот же принцип внутренних слотов, но нужны собственный компонент и модель Heat; маскировать охладитель под броню/оружие не следует. Несколько бронеплит требуют правил распределения повреждений, несколько сканеров — выбора/объединения, несколько тракторов — управления эмиттерами и лучами. В первой реализации этих правил нет.

Перки и временные бустеры должны менять эффективные параметры устройств, по умолчанию сохраняя установочный класс. См. [перки и бустеры](perks_and_boosters.md). Расширяемый реестр семейств, теги слотов, политики снятия, инструмент миграции, подробные коды отказа и согласование возможностей в мультиплеере остаются будущими задачами.
