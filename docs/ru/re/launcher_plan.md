# Лаунчер и живые переключатели

То, что сейчас подменяется перед запуском, должен переключать движок.
Лаунчер только пишет ключи и проверяет, что игра вообще может стартовать.
Целиком игру он не пересобирает и ini не затирает.

Текущий Python-лаунчер для этого не годится. Он копирует весь
`BUILDS/<язык>_<сложность>` поверх корня и затем заново пишет
`contrail.ini`, `bodyparts_player.ini`, `cameras.ini`, `fonts.ini`,
`HudShift.ini`, `front_light.ini`. Список шкур закрытый, в `startup/meta.json`.
Перчатки прибиты к телу. Для этого нужны Python, WebView2 и весь Pythonlancer.

## Движок, не файл

`PerfOptions.ini` движок уже читает (`graphics_settings.cpp`). Туда и класть
живые переключатели. Применение — в том месте, где костюм или эффект уже
собирается для клиента, а не подменой `DATA/CHARACTERS/bodyparts_player.ini`.

Ключи, первая очередь:

- `player_body`, `player_head`, `player_lefthand`, `player_righthand` —
  никнеймы из `bodyparts.ini`, не пути к мешам.
- `player_accessory` — повторяемый. Шлем связи и шапка живут здесь.
- `story_body`, `story_head`, `story_lefthand`, `story_righthand`,
  `story_accessory` — тот же набор для сюжетной катсцены, где игрок на экране.
  Если сюжетного ключа нет, берётся обычный.

Бар и комната берут обычный набор. Катсцена сюжета берёт `story_*`, если он
задан. Сейв при этом не переписывается: оверрайд только на показ.

Контраил так же. Не затирать `contrail.ini`. Ключ `player_contrail` в
`PerfOptions` подменяет `vis_effect` у `player_contrail` в момент привязки
эффекта. Список значений — никнеймы `EFT_ENGINE_CONTRAIL` из FX, не словарь
лаунчера.

`cameras.ini`, шрифты, сдвиг HUD и передний свет — тем же правилом, после
костюма и контраила. Пока ключа в движке нет, лаунчер этот файл не трогает.

## Шапка

Шапка выключена не из-за меша. Сейв пишет только `body`, `head`, `lefthand`,
`righthand`. Строку `accessory` загрузчик понимает
(`server_savegame.cpp`, суффикс `accessory`), писатель её не выдаёт.
Поэтому шапка не переживает сохранение.

Хак лаунчера подменял меш `player_prop_hat` в `bodyparts_player.ini`.
Надетый костюм берётся из сейва, а в сейве этого аксессуара нет. Хак не
держался. Повторять его нельзя.

Пока писатель сейва не пишет `accessory` и `com_accessory`, пункт шапки в
лаунчере выключен, с этой причиной в подписи. Включать его вместе с записью
сейва, не раньше.

## Лаунчер

Один exe на Win32. Без Python, без WebView2, без копирования `BUILDS`.

Перед стартом проверяет `freelancer.exe`, каталог `DATA` и VC++ 2015–2022 x86.
Нет компонента — предлагает установить `redist\vc_redist.x86.exe` из комплекта
лаунчера. Если файла нет, показывает ссылку
`https://aka.ms/vc14/vc_redist.x86.exe`.

DLSS 5 включается только здесь. Лаунчер проверяет адаптер NVIDIA и файлы
помощника. Нет поддержки — пишет `enabled=0` и убирает `bin\dxgi.dll` и
`bin\D3D9.dll` в `bin\neural\off`, чтобы ReShade не грузился. Включение
возвращает эти два файла. Пока игра запущена, файлы не двигаются.

Экран шкур читает уже лежащие никнеймы и меши (`bodyparts.ini`,
`DATA/CHARACTERS`). Пишет только ключи `PerfOptions`. `bodyparts_player.ini`
не открывает. Перчатки выбираются отдельно, не по таблице тела.

Прогрев шейдеров и установщик — отдельные задачи из `TODO.md`, не этот этап.

## Порядок

1. Движок читает костюм из `PerfOptions` и подставляет его при сборке костюма
   игрока на базе и в сюжетной катсцене.
2. Сейв пишет и читает `accessory` / `com_accessory`. После этого включается шапка.
3. Тот же приём для контраила, затем для камер, шрифтов, HUD и переднего света.
4. Тонкий лаунчер: проверка зависимостей и запись этих ключей.
5. У Python-лаунчера убрать `copytree` сборки и шаблоны, которые затирают ini.
