# Улучшения частиц (FREELANCER_PARTICLE_FX)

Нет в оригинальной игре. Флаг сборки `FreelancerParticleFx` (клиент и `alchemy.dll`); сами
мягкие частицы живут в `RP9.dll` и требуют конвейер Direct3D 9 с глубиной сцены INTZ. Всё
включается в `port.ini`:

```ini
[Render]
soft_particles_effects = 6   ; метры; 0 = выключено
soft_particles_clouds = 60   ; метры; 0 = выключено
cloud_sort = 1
cloud_smooth_fade = 1
```

Блок выше — пример включения. В рабочем `bin/port.ini` установлено
`soft_particles_effects = 0`. 2026-10-27 по запросу пользователя также выключена
эта настройка в установленной игре: дополнительное смягчение взрывов, огня и дыма,
включая частицы с `XP_HERM`. Исходные ALE и текстуры не изменены. Это смягчение по
глубине, а не тепловое преломление; после изменения нужен перезапуск игры.

## Мягкие частицы

Ретейл-частицы — плоские спрайты с жёстким тестом глубины: где взрыв, огонь или облачко
туманности проходит сквозь корабль, станцию или астероид, оно срезается по резкой линии.

`IRenderPipelineEx::SetSoftParticles(kind)` просит RP9 рисовать следующие отрисовки
фиксированного конвейера через встроенный шейдер (`RP9Ex.cpp`, `DATA_EXTRA` не нужен). Шейдер
повторяет фиксированный конвейер (трансформация, stage 0 select / modulate текстуры и цвета
вершины, туман) и умножает альфу (при аддитивном `ONE` ещё и цвет) на
`saturate((глубина сцены - глубина частицы) / расстояние затухания)`. Тест глубины заменяется
этим затуханием, поэтому глубину сцены (INTZ) можно читать.

Подходит только отрисовка, похожая на частицы: вершины `XYZ | DIFFUSE | TEX`, смешивание с
источником `SRCALPHA` или `ONE`, тест глубины включён, запись глубины выключена, освещение
выключено, stage 0 — select или modulate текстуры и цвета, stage 1 выключен. Всё остальное
рисуется как раньше.

Кто включает:
- `alchemy.dll`: отрисовки `FxBasicAppearance` (взрывы вроде `XP_HERM`, огонь, дым),
  `FxRectAppearance`, `FxPerpAppearance` и `FxOrientedAppearance` (вид `effects`);
- облачка внутри туманности, `TexturePanelDrawClouds` (вид `clouds`).

## Облачка туманности

- `cloud_sort`: облачка рисуются от дальних к ближним, перекрывающиеся полупрозрачные пуфы
  смешиваются в правильном порядке и не мерцают.
- `cloud_inside_only`: облачка рисуются только пока камера внутри зоны туманности, и только
  те, что лежат внутри зоны, — снаружи сферу облачков не видно.
- `cloud_smooth_fade`: затухание на краю сферы пуфов и вблизи камеры (`near_fade_distance`)
  идёт по smoothstep, а не линейно, пуфы не «выскакивают».

## Ключи облака в `[Clouds]`

Необязательные ключи секции `[Clouds]` (туманности или кольца, например облака-подсветки на
всю систему); оригинальная игра их игнорирует. Работают только с `FreelancerParticleFx`.

```ini
[Clouds]
puff_facing = individual   ; каждый пуф смотрит на точку камеры и держит свой устойчивый угол
puff_spin = 0.5            ; градусов в секунду медленного вращения (0 = нет)
soft_fade = 2000           ; мягкие частицы для этого облака, метры (0 = из port.ini)
far_fade = 0.55, 1.0       ; плавное дальнее затухание между этими долями радиуса сферы пуфов
depth_tint = 20, 40, 110, 0.6     ; воздушная перспектива: цвет (0..255) и сила (0..1)
depth_tint_range = 11000, 22000   ; метры от камеры: где оттенок начинается и где он полный
sun_scatter = 1.2, 0.6            ; рассеяние света: сила, направленность вперёд (-0.9..0.9)
```

- `depth_tint`: дальние пуфы плавно (smoothstep по `depth_tint_range`) уходят в заданный цвет,
  как синеет далёкий воздух; глаз считывает это как расстояние.
- `sun_scatter`: источник света — центр зоны, которой принадлежат облака (для кольца вокруг
  солнца — солнце). Пуф, который камера видит в сторону света, ярче и чуть плотнее (фаза
  Хеньи-Гринштейна, нормированная на пик вперёд); освещённый из-за спины камеры тускнеет до 0,6.
  В туманности источник — центр её зоны, так что ключ рассчитан на кольца.

- `puff_facing = individual`: ретейл поворачивает все пуфы одной общей осью, которая следует
  за камерой, и держит квадраты параллельно экрану, поэтому огромные пуфы «плывут» и
  поворачиваются вместе с камерой. Здесь каждый квадрат смотрит на точку камеры и держит свой
  угол.
- `far_fade`: вместо ретейлового линейного затухания между 0,7 и 1,0 радиуса сферы (по
  квадратам расстояний) — smoothstep между двумя заданными долями.
